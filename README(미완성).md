🎨 ART-LOG: 개인 맞춤형 전시 큐레이션 플랫폼
AI 기술을 활용하여 예술적 경험을 데이터로 기록하고, 사용자 취향에 맞는 전시를 추천하는 개인화 플랫폼입니다.


📅 프로젝트 개요

타겟: MZ세대 및 해외 관광객
핵심 가치: AI 큐레이션, 실시간 전시 지도, AI 도슨트 이미지 스캔, 개인화 기록 관리
배포 URL: (Vercel을 통한 배포 완료)


🛠 기술 스택

Frontend: React, TypeScript, Vite
Styling: Pure CSS (BEM 방법론), Lucide-React (Icons)
API & Library: Kakao Maps API, Portone (결제 API)
Deployment: Vercel



🚀 주요 구현 기능
1. 메인 페이지 및 하단 네비게이션 구축
전체적인 레이아웃 구축 : 메인페이지, 지도, 가이드, 코스, 기프트 네비게이션 제작
             : 해당 페이지 뼈대 레이아웃 + 디테일 구축
             : 메인 페이지 (전체적인 레이아웃 순서 지정 및 레이아웃 구축,알림, 메인페이지 내 추천 나들이 코스, 전체 전시 목록, 도슨트 페이지 연결, 전체보기 파트에 view-all 기능 탑재)
             : 지도 (api 연결할 지도 탭, 아래서 위로 슬라이드 가능한 리스트, 검색 기능 및 레이아웃, 현재 위치로 이동, 
                    리스트에서 전시/공연 클릭 혹은 핑 클릭시 중심축 재이동)
             : 가이드 (인간 / ai 구분) 예약하기, 해설 페이지 레이아웃 구축 , 오디오 탭 디자인
             : 코스 (화면 레이아웃 구성만)
             : 기프트 (화면 레이아웃 구성만)
             : 알림 (디자인, 안 읽음 / 읽음 구분 / 전체 읽음 로직)
             : 마이페이지 (배지 기능 제외 페이지 전체적인 레이아웃 및 기능 제작)
             : 로그인 후 취향분석 페이지 (레이아웃 제작, 선택시 하단에 n개 선택 로직 구축)

모바일 최적화: Viewport 설정 및 폰트 사이즈(16px) 조정을 통해 입력 시 화면 강제 확대 방지.




2. 위치 기반 서비스 및 인터랙티브 UI (Map & Navigation)

카카오 맵 연동: Geolocation API 연동

커스텀 바텀 시트: 라이브러리(Framer-motion) 없이 순수 JS(Touch Event)로 드래그 및 스냅 기능을 직접 구현하여 성능 최적화.

스마트 스크롤: 메인의 코스 부분에서 아이콘 누르면 scrollIntoView를 활용해 코스 선택 시 해당 위치로 자동 스크롤되는 UX 제공.




3. AI 도슨트 스캔 (AI Scanner)

스캔 UI/UX: 사용자가 이미지를 올리면 AI 가 스캔, 해설 페이지 출력, 4개 국어 번역 서비스가 원활하도록 연결 및 레이아웃 구축

도슨트 서비스: 작품 분석 결과 제공 및 가이드 음성 재생을 위한 하단 고정형 미니 플레이어 최적화.



4. 커머스 및 결제 시스템 (Commerce & Payment)

장바구니 로직: 데이터 타입(문자열/숫자)에 유연한 가격 합산 정규식 적용 및 Key 충돌 방지 처리.

포트원(아임포트) 연동: 카카오페이 등 간편결제 모듈 연동 및 handleOrder 로직 작성.

모바일 결제 대응: iOS 카드사 앱 복귀를 위한 app_scheme 및 결제 결과 자동 감지를 위한 useEffect 분석 로직 구현.




5. 마이페이지 및 활동 관리 (MyPage)

상태 기반 뷰 전환: viewState를 활용해 프로필, 전시 기록, 친구 관리 등 복잡한 메뉴를 단일 페이지 내에서 매끄럽게 전환.

실시간 프리뷰: useRef와 FileReader를 활용해 서버 업로드 전 프로필 이미지 실시간 변경 기능 구현.

상호작용: 친구 목록에서 선물하기 클릭 시 부모 컴포넌트의 상태를 변경하여 즉시 기프트탭으로 이동(onTabChange) 처리.


6. 나들이 코스 
코스 메인 탭 뼈대 레이아웃 구축 
onClick , setTargetCourse('course-jongno'); , setActiveTab('course'); 등 코드를 이용해 코스 탭으로 이동시 연결된 코스로 자동 스크롤 구현




7. 백엔드 연동

프론트엔드-백엔드 데이터 형식 통합

JSON 응답 처리: 서버가 주는 데이터를 JSON으로 받도록 코드를 수정하고, 로그인 성공 시 accessToken을 localStorage에 저장하도록 로직을 구현했습니다.

필드명 일치: 백엔드의 User 엔티티 구조에 맞춰 아이디는 loginId, 비밀번호 확인은 passwordConfirm 등의 명칭을 사용하도록 전송 파라미터를 맞췄습니다.

2. 서버 연결 및 에러 해결
Connection Refused 해결: net::ERR_CONNECTION_REFUSED 에러가 발생했을 때, 서버가 꺼져 있음을 확인하고 직접 백엔드 폴더에서 Spring Boot 서버를 실행하여 연결을 성공시켰습니다.

주소(URL) 최적화: 서버 로그의 404 Not Found 기록을 바탕으로 API 경로를 점검했으며, 중복 확인 시 ?loginId=... 형태로 데이터를 보내도록 수정했습니다.

3. 코드 문법 및 로직 교정
Async/Await 오류 수정: 컴포넌트 외부에서 잘못 사용된 await 문장을 삭제하여 리액트 페이지가 정상적으로 렌더링되지 않던 문제를 해결했습니다.

상태 관리: 아이디 중복 확인 여부(isIdChecked), 로딩 상태(isLoading), 비밀번호 표시 토글(showPw) 등 사용자 경험(UX)을 위한 기능들을 통합했습니다.



1. 인증 오류 해결 (OpenAI API Key)
문제: 서버 응답 데이터에 401 (invalid_api_key) 에러가 뜨며 AI 기능이 멈춤.

원인: 백엔드 서버의 .env 파일에 설정된 OpenAI API 키가 만료되었거나 형식이 잘못됨(따옴표 등).

조치: 새 API 키를 발급받아 .env에 공백과 따옴표 없이 저장하고, load_dotenv()를 통해 서버가 새 키를 인식하도록 백엔드 터미널을 재시작함.

2. 데이터 구조 매핑 (Front-End)
문제: 서버에서 데이터를 보내줘도 화면에 아무 변화가 없는 "무반응" 상태 발생.

원인: 서버가 주는 데이터 형식(resData.data.places...)과 리액트 코드에서 사용하는 변수명이 일치하지 않아 스크립트가 중간에 멈춤.

조치: RootPage.tsx에서 **Optional Chaining(?.)**을 도입하여 데이터가 일부 누락되어도 에러 없이 기본값을 보여주도록 방어 코드를 작성함.

3. 백엔드 논리 오류 수정 (KeyError: 'url')
문제: API 키 해결 후 {status: 'error', message: "'url'"} 에러 발생.

원인: ai_service.py가 생성한 결과물 구조와 main.py에서 꺼내 쓰려는 경로가 서로 달랐음 (객체 안에 없는 'url' 키를 강제로 참조함).

조치: main.py에서 데이터를 추출할 때 plan["places"] 경로를 정확히 짚어주도록 수정하고, get() 메서드를 사용해 데이터가 없어도 서버가 죽지 않게 설정함.

4. 사용자 경험(UX) 개선
문제: 서버 에러 시 로딩 인디케이터(아티가 설계 중입니다...)가 영원히 사라지지 않음.

조치: try-catch-finally 구문을 활용해, **성공하든 실패하든 무조건 로딩 상태를 해제(setIsGenerating(false))**하도록 로직을 보강함.





🛠 기술적 해결 및 최적화 (Technical Challenges)

컴포넌트 모듈화: ExhibitCard, NotificationItem 등 공통 UI를 분리하여 재사용성 및 유지보수성 향상.

스크롤 UX 개선: scrollbar-width: none을 통해 브라우저 스크롤바를 숨겨 디자인 완성도를 높이되 기능은 유지.

레이아웃 안정화: 하단 내비게이션 바에 콘텐츠가 가려지지 않도록 전역 padding-bottom 확보 및 시각적 균형 보정.

상태 유지: LocalStorage를 활용하여 새로고침 시에도 사용자 알림 설정값 등이 유지되도록 설계.
